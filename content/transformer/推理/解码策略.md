# 解码策略

训练时模型学的是：

```text
给定上下文，预测下一个 token 的概率分布
```

推理时还要决定：

```text
从这个概率分布里怎么选下一个 token？
```

这就是解码策略。

## Greedy Decoding

每一步都选概率最高的 token。

```text
下一个 token = argmax(prob)
```

优点：

- 简单。
- 稳定。
- 速度快。

缺点：

- 容易死板。
- 可能陷入局部最优。
- 多样性差。

适合：

```text
确定性任务
代码补全
简单问答
需要稳定输出的场景
```

## Sampling

Sampling 是按概率随机抽样。

比如：

```text
猫：0.6
狗：0.3
车：0.1
```

模型不一定每次都选“猫”，也可能按概率选到“狗”。

优点：

- 更有多样性。
- 适合开放式生成。

缺点：

- 可能不稳定。
- 可能选到低质量 token。

## Temperature

Temperature 控制分布的尖锐程度。

通常做法：

```text
softmax(logits / temperature)
```

如果 temperature 小：

```text
分布更尖锐
模型更保守
更接近 greedy
```

如果 temperature 大：

```text
分布更平
随机性更强
更有创造性
```

直觉：

```text
temperature = 0.7：更稳
temperature = 1.0：正常
temperature = 1.5：更随机
```

## Top-k Sampling

Top-k 是只从概率最高的 k 个 token 里采样。

比如 `k=5`：

```text
只保留前 5 个候选词
其他词概率置 0
```

这样可以避免采到特别离谱的低概率 token。

缺点是 k 固定，不管当前分布是否已经很确定。

## Top-p Sampling

Top-p 也叫 nucleus sampling。

它不是固定保留 k 个，而是保留累计概率达到 p 的最小集合。

比如 `p=0.9`：

```text
从高到低排序
一直保留 token，直到累计概率超过 0.9
```

如果模型很确定，候选集合会很小。
如果模型不确定，候选集合会变大。

所以 top-p 通常比 top-k 更灵活。

## Beam Search

Beam Search 不只保留一个候选，而是同时保留多个候选序列。

比如 beam size = 4：

```text
每一步保留当前总分最高的 4 条路径
```

适合机器翻译、摘要这类更看重整体概率的任务。

但在开放式对话里，beam search 有时会让输出变得重复和保守。

## 为什么会重复

语言模型生成时，可能出现：

```text
我觉得这个问题很重要，这个问题很重要，这个问题很重要...
```

原因可能是：

- 模型对某段模式概率很高。
- 解码策略太保守。
- 没有重复惩罚。
- 上下文进入循环。

常见缓解：

- repetition penalty。
- no-repeat ngram。
- 调高 temperature。
- 使用 top-p。

## 推理和训练的关系

训练改变的是模型权重。

解码策略不改变模型权重，只改变怎么从概率分布里选 token。

所以同一个模型：

```text
greedy 输出可能很稳
sampling 输出可能更多样
temperature 高时可能更发散
```

这不是模型变了，而是选择 token 的策略变了。

## 一句话总结

模型负责给出：

```text
下一个 token 的概率分布
```

解码策略负责决定：

```text
怎么从这个分布里选 token
```

理解这点后，你就能区分“模型能力问题”和“采样参数问题”。
