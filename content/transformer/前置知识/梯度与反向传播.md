# 梯度与反向传播

很多 Transformer 教程会直接讲 Attention，但其实更前面还有一个问题：

```text
模型到底是怎么从“不会”变成“会一点”的？
```

答案不是模型自己悟了，而是每次预测之后，它都会收到一个反馈：这次错得有多离谱。然后模型根据这个反馈，微调自己的权重。

这背后最核心的东西就是：**梯度**。

## 梯度是什么

一句话理解：

**梯度就是告诉参数：如果你想让损失变小，应该往哪个方向改、改多少。**

比如模型里有一个权重 `w`，它影响最终预测。训练时我们会计算：

```text
梯度 = 损失函数对 w 的导数
```

写成数学符号就是：

```text
dLoss / dw
```

这个值的意思是：

```text
w 稍微变大一点，Loss 会怎么变？
```

如果梯度是正的，说明 `w` 变大可能让 loss 变大，那我们就应该让 `w` 变小。
如果梯度是负的，说明 `w` 变大可能让 loss 变小，那我们就应该让 `w` 变大。

所以最常见的更新公式是：

```text
新权重 = 旧权重 - 学习率 × 梯度
```

这里的减号不是随便写的。因为梯度指向的是 loss 上升最快的方向，训练要让 loss 下降，所以要反着走。

## 用下山理解梯度

你可以把 loss 想成一座山的高度。

```text
位置 = 当前权重
高度 = 当前 loss
坡度 = 梯度
```

训练的目标就是从山上往低处走。

```text
梯度很大：坡很陡，说明当前位置改一点，loss 变化很明显
梯度很小：坡很平，说明当前位置怎么改，loss 都变化不大
梯度为 0：局部看起来已经没有明显下降方向
```

但这里要注意：**梯度为 0 不一定代表模型已经最好了。**
它可能是真的到达了比较好的位置，也可能只是卡在了一个平坦区、鞍点，或者学习率设置不合适。

## 什么是反向传播

前向传播是从输入算到输出：

```text
输入 x
  ↓
模型
  ↓
预测 y_hat
  ↓
loss
```

反向传播就是倒着问每个参数：

```text
这次 loss 这么大，你应该负多少责任？
```

比如一个三层网络：

```text
x -> 第1层 -> 第2层 -> 第3层 -> loss
```

反向传播会从 loss 开始往回算：

```text
loss 对第3层参数的梯度
loss 对第2层参数的梯度
loss 对第1层参数的梯度
```

这件事靠的是链式法则。

## 链式法则为什么重要

神经网络不是一个简单公式，而是一层套一层：

```text
loss = f3(f2(f1(x)))
```

如果想知道第1层参数对最终 loss 的影响，就必须一路乘回来：

```text
第1层影响第2层
第2层影响第3层
第3层影响 loss
```

所以深层网络训练难，本质上和这个“连续相乘”有很大关系。

如果一路乘的数都小于 1，梯度会越来越小，这就是 [[梯度消失]]。
如果一路乘的数都大于 1，梯度会越来越大，这就是 [[梯度爆炸]]。

Transformer 里的 [[Add]]、[[LayerNorm]]、合适的初始化、学习率策略，都是为了让这个反向传播过程更稳定。

## 权重什么时候会变化

权重会不会变化，主要看三个东西：

```text
学习率
梯度
优化器状态
```

最简化的情况：

```text
新权重 = 旧权重 - 学习率 × 梯度
```

所以只要 `学习率 × 梯度` 不为 0，权重就会变化。

## 权重什么时候基本不再变化

这件事很重要，因为它对应“模型是不是还在学习”。

### 1. 梯度接近 0

如果梯度很小：

```text
梯度 = 0.0000001
学习率 = 0.001
更新量 = 0.0000000001
```

这个更新量太小，权重几乎不动。

这可能是好事，也可能是坏事。

好事是：模型已经接近一个比较稳定的位置，loss 不怎么降了。
坏事是：模型进入了梯度消失，前面层几乎收不到学习信号。

### 2. 学习率太小

即使梯度不小，如果学习率太小，更新也会很慢。

```text
梯度 = 1
学习率 = 0.00000001
更新量 = 0.00000001
```

这不是模型不会学，而是每一步走得太小。

### 3. 参数被冻结

有些训练会故意冻结部分参数，比如微调大模型时只训练 LoRA 或最后几层。

被冻结的参数不会更新，即使它理论上能算出梯度。

在 PyTorch 里通常是：

```python
param.requires_grad = False
```

### 4. 训练已经停止

推理阶段不会更新权重。

比如你用 GPT 生成文字时，它不会因为刚刚回答了一句话就立刻改变模型内部权重。

推理时发生的是：

```text
固定权重
输入 token
计算下一个 token 概率
采样或选择 token
继续生成
```

权重只有在训练或微调时才会被优化器更新。

### 5. 优化器没有拿到这个参数

有时参数本身 `requires_grad=True`，但你没有把它传给优化器，它也不会更新。

```python
optimizer = torch.optim.AdamW(model.some_part.parameters(), lr=1e-4)
```

这行代码只会更新 `some_part`，模型其他部分不会被这个优化器更新。

## Loss 不变等于权重不变吗

不一定。

有几种情况：

- loss 不变，但权重还在微小变化。
- loss 上下震荡，说明学习率可能偏大或 batch 噪声比较明显。
- loss 不降，可能是模型能力不足、数据有问题、学习率不合适、mask 写错、标签错位。
- loss 降得很快但验证集变差，可能是过拟合。

所以判断模型有没有学，不能只看一个 batch 的 loss。
更稳妥的是看：

```text
训练 loss 趋势
验证 loss 趋势
梯度范数
学习率曲线
生成样例
```

## 在 Transformer 里梯度流过哪里

一层 Transformer 大概是：

```text
x
  ↓
Self-Attention
  ↓
Add & Norm
  ↓
Feed Forward
  ↓
Add & Norm
```

训练时，loss 的梯度会从最后输出一路传回来。

注意力里的 `W_Q`、`W_K`、`W_V`、`W_O` 会更新。
前馈网络里的线性层权重会更新。
LayerNorm 里的 `gamma`、`beta` 会更新。
词嵌入矩阵通常也会更新。

但固定正弦位置编码不会更新，因为它不是可学习参数。

## 一句话总结

梯度不是一个玄学词，它就是“每个参数对错误负多少责任”的量化结果。

反向传播负责把这个责任从 loss 一层层传回去，优化器再根据梯度修改权重。

Transformer 能训练得深，不只是因为 Attention 强，也因为它用了残差连接、归一化、合适的初始化和优化策略，让梯度能比较稳定地传回去。
