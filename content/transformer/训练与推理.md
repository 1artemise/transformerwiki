# 训练与推理

学 Transformer 时，很容易把“训练”和“生成”混在一起。

但它们其实是两件事：

```text
训练：模型看答案，计算自己错在哪里，然后更新权重
推理：模型不再改权重，只根据当前输入一步步生成结果
```

理解这个区别后，很多问题会变清楚：为什么训练时要 mask？为什么推理时不能并行生成整句话？为什么模型用完不会自动学习？

## Transformer 训练时在做什么

以语言模型为例，训练目标通常是预测下一个 token。

比如一句话：

```text
我 喜欢 吃 苹果
```

训练时可以拆成：

```text
输入：我
目标：喜欢

输入：我 喜欢
目标：吃

输入：我 喜欢 吃
目标：苹果
```

模型每次输出的不是一个词，而是整个词表上的分数：

```text
苹果：8.2
香蕉：4.1
喜欢：0.7
...
```

这些分数会经过 [[前置知识/softmax|softmax]] 变成概率，再用 [[前置知识/损失函数|损失函数]] 判断正确答案的概率够不够高。

## 一次训练迭代的流程

可以记成这条线：

```text
准备输入和标签
  ↓
前向传播
  ↓
计算 loss
  ↓
反向传播算梯度
  ↓
优化器更新权重
  ↓
清空梯度，进入下一轮
```

对应到 PyTorch 大概是：

```python
logits = model(input_ids)
loss = loss_fn(logits, labels)

optimizer.zero_grad()
loss.backward()
optimizer.step()
```

这里每一步都很重要：

- `model(input_ids)`：用当前权重做预测。
- `loss_fn`：衡量预测和答案差多少。
- `zero_grad()`：清掉上一轮梯度，不然梯度会累加。
- `backward()`：反向传播，计算每个参数的梯度。
- `step()`：优化器真正修改权重。

## Teacher Forcing 是什么

在原始 Transformer 翻译任务里，解码器训练时会看到“正确答案的前半段”，然后预测下一个词。

比如目标句子：

```text
I like cats
```

训练时预测 `like`，输入给解码器的是：

```text
I
```

预测 `cats`，输入给解码器的是：

```text
I like
```

也就是说，训练时前面喂的是标准答案，而不是模型自己刚刚生成的错误答案。

这样训练更稳定，模型能更快学会“在正确上下文下该输出什么”。

但这也带来一个问题：推理时模型看不到标准答案，只能看自己已经生成的内容。所以如果前面生成错了，后面可能一路偏下去。

## 为什么训练时还要 Mask

训练时虽然整句答案都在数据里，但模型不能偷看未来。

比如预测 `like` 时，如果模型能看到后面的 `cats`，那它就不是在学语言生成，而是在抄答案。

所以 decoder 的 self-attention 要加 causal mask：

```text
当前位置只能看自己和前面的 token
不能看后面的 token
```

## 推理时在做什么

推理时权重固定，不再更新。

比如模型要生成一句话：

```text
我 喜欢
```

它会先预测下一个 token：

```text
吃：0.6
看：0.2
跑：0.1
...
```

如果选择了“吃”，下一步输入就变成：

```text
我 喜欢 吃
```

再预测下一个 token。

所以推理是自回归的：

```text
生成第1个 token
生成第2个 token
生成第3个 token
...
```

这也是为什么大语言模型生成长文本会慢：每一步都依赖前一步的结果。

## 训练和推理最大的区别

| 对比 | 训练 | 推理 |
| --- | --- | --- |
| 是否更新权重 | 更新 | 不更新 |
| 是否计算 loss | 计算 | 通常不计算 |
| 是否反向传播 | 是 | 否 |
| Dropout | 开启 | 关闭 |
| BatchNorm | 用 batch 统计量 | 用移动平均 |
| LayerNorm | 行为基本一致 | 行为基本一致 |
| 目标 | 让模型学会 | 让模型输出 |

所以你平时调用一个模型，它不会因为你问了一个问题就把权重改掉。
它只是把上下文作为输入，在固定权重下计算输出。

## 什么叫收敛

收敛不是“模型突然训练完美”，而是训练逐渐进入一个变化很小的状态。

常见表现是：

```text
训练 loss 下降越来越慢
验证 loss 不再明显下降
梯度范数比较稳定
生成结果不再明显变好
```

这时权重不是绝对不变，而是更新幅度变小。

如果继续训练，可能还有一点提升，也可能开始过拟合。

## 什么时候应该停止训练

常见判断方法：

- 验证集 loss 连续多轮不下降。
- 训练 loss 继续下降，但验证 loss 上升。
- 生成样例已经达到当前目标。
- 梯度经常爆炸或 loss 变成 NaN，需要先排查训练配置。
- 学习率已经降到很小，继续训练收益很低。

这里不要只看训练集。训练集变好只能说明模型越来越会做练习题，验证集变好才说明它学到了一点通用规律。

## Transformer 里哪些参数会被训练

通常会训练：

- token embedding 矩阵
- 注意力里的 `W_Q`、`W_K`、`W_V`、`W_O`
- 前馈网络里的线性层
- LayerNorm 的 `gamma` 和 `beta`
- 输出词表投影层

不一定训练：

- 固定 sin/cos 位置编码
- 冻结的预训练模型参数
- 只做 LoRA 微调时的原始大模型权重

所以看到一个模块时，可以顺手问一句：

```text
这里有没有可学习参数？
它会不会被优化器更新？
它训练和推理时行为一样吗？
```

这个习惯很重要。

## 一句话总结

训练是在用 loss 和梯度改权重；推理是在固定权重下生成 token。

Transformer 的结构讲的是“怎么算”，训练流程讲的是“怎么学”，推理流程讲的是“怎么用”。这三件事合起来，才是一个完整模型。
