# 张量维度流

学 Transformer 时，很多人不是卡在概念，而是卡在形状。

比如你知道 attention 是：

```text
softmax(QK^T / sqrt(d_k))V
```

但一到代码里就会问：

```text
Q 到底几维？
K 为什么要转置？
多头为什么要 transpose？
loss 前为什么要 reshape？
```

这篇专门把维度走一遍。

## 先定一组符号

假设：

```text
B = batch size = 2
S = source sequence length = 5
T = target sequence length = 4
D = d_model = 512
H = num_heads = 8
Dh = head_dim = D / H = 64
Vocab = 30000
```

你可以先记住：

```text
B：一次处理几句话
S/T：一句话有几个 token
D：每个 token 用多少维向量表示
H：几个注意力头
Dh：每个头分到多少维
```

## 输入 token

原始输入不是文字，而是 token id。

```text
src: [B, S] = [2, 5]
tgt: [B, T] = [2, 4]
```

比如：

```text
src[0] = [12, 45, 998, 7, 2]
```

每个数字代表词表里的一个 token。

## Embedding 后

Embedding 会把每个 token id 查表变成向量。

```text
src_embedding: [B, S, D] = [2, 5, 512]
tgt_embedding: [B, T, D] = [2, 4, 512]
```

意思是：

```text
2 句话
每句话 5 个 token
每个 token 512 维
```

位置编码也是 `[1, S, D]` 或 `[1, T, D]`，可以广播相加。

```text
x = token_embedding + positional_encoding
```

加完形状不变：

```text
x: [B, S, D]
```

## Q、K、V 的形状

在 self-attention 里：

```text
Q = XW_Q
K = XW_K
V = XW_V
```

如果 `X` 是：

```text
X: [B, S, D]
```

线性层 `W_Q/W_K/W_V` 都是从 `D -> D`，所以：

```text
Q: [B, S, D]
K: [B, S, D]
V: [B, S, D]
```

注意：虽然形状一样，但内容不一样，因为三套权重不同。

## 拆成多头

多头注意力要把最后一维拆成：

```text
D = H × Dh
512 = 8 × 64
```

所以先 reshape：

```text
[B, S, D] -> [B, S, H, Dh]
```

然后 transpose，变成：

```text
[B, H, S, Dh]
```

为什么要把 `H` 提到前面？

因为这样每个 head 可以独立算注意力：

```text
每个 head 看到的是 [S, Dh]
```

代码里常见：

```python
x = x.view(B, S, H, Dh)
x = x.transpose(1, 2)
```

## QK^T 的形状

现在：

```text
Q: [B, H, S, Dh]
K: [B, H, S, Dh]
```

要算每个 token 看每个 token 的分数，所以 K 要转置最后两维：

```text
K^T: [B, H, Dh, S]
```

矩阵乘法：

```text
Q @ K^T
[B, H, S, Dh] @ [B, H, Dh, S] -> [B, H, S, S]
```

这个 `[S, S]` 就是注意力分数矩阵。

如果 `S = 5`，它表示：

```text
第1个 token 看 5 个 token 的分数
第2个 token 看 5 个 token 的分数
...
第5个 token 看 5 个 token 的分数
```

## softmax 后

softmax 在最后一维做：

```text
attention_weight: [B, H, S, S]
```

最后一维加起来等于 1。

也就是对每个 token 来说，它分配了一个“看其他 token 的注意力比例”。

## 乘 V

现在：

```text
attention_weight: [B, H, S, S]
V:                [B, H, S, Dh]
```

相乘：

```text
[B, H, S, S] @ [B, H, S, Dh] -> [B, H, S, Dh]
```

含义是：

```text
每个 token 用注意力权重，把所有 token 的 V 加权求和
```

## 多头合并

attention 输出现在是：

```text
[B, H, S, Dh]
```

要合并回：

```text
[B, S, D]
```

代码里通常：

```python
x = x.transpose(1, 2).contiguous()
x = x.view(B, S, D)
```

`contiguous()` 是因为 transpose 后内存不一定连续，直接 view 可能报错。

## Encoder 输出

编码器每层输入输出形状都一样：

```text
[B, S, D] -> [B, S, D]
```

这点很重要。

因为残差连接要求：

```text
x + sublayer(x)
```

两者形状必须一样。

所以 attention 和 feed forward 最后都会回到 `D` 维。

## Feed Forward 维度

Transformer 里的 FFN 通常是：

```text
D -> Dff -> D
```

原论文里：

```text
D = 512
Dff = 2048
```

形状变化：

```text
[B, S, 512]
  -> Linear(512, 2048)
[B, S, 2048]
  -> 激活函数
[B, S, 2048]
  -> Linear(2048, 512)
[B, S, 512]
```

为什么最后要回到 512？

因为后面还要做残差连接：

```text
x + ffn(x)
```

## Decoder 的 Cross-Attention 维度

Cross-Attention 里：

```text
Q 来自 decoder
K、V 来自 encoder
```

如果：

```text
decoder hidden: [B, T, D]
encoder output: [B, S, D]
```

那么：

```text
Q: [B, H, T, Dh]
K: [B, H, S, Dh]
V: [B, H, S, Dh]
```

QK^T：

```text
[B, H, T, Dh] @ [B, H, Dh, S] -> [B, H, T, S]
```

这个矩阵表示：

```text
每个目标 token，看每个源 token 的分数
```

所以 Cross-Attention 允许输入长度和输出长度不同。

## 输出到词表

Decoder 最后输出：

```text
decoder_output: [B, T, D]
```

经过线性层映射到词表：

```text
logits = Linear(D, Vocab)
```

形状：

```text
logits: [B, T, Vocab]
```

如果词表 30000：

```text
[2, 4, 30000]
```

意思是：

```text
2 句话
每句话 4 个位置
每个位置都有 30000 个词的分数
```

## 为什么 loss 前要 reshape

PyTorch 的 `CrossEntropyLoss` 通常希望输入是：

```text
[N, C]
```

其中：

```text
N = 样本数
C = 类别数
```

但 Transformer 输出是：

```text
logits: [B, T, Vocab]
labels: [B, T]
```

所以要摊平：

```python
loss = criterion(
    logits.reshape(-1, logits.size(-1)),  # [B*T, Vocab]
    labels.reshape(-1),                   # [B*T]
)
```

这里的每个 token 位置，都相当于一个分类样本。

## 最容易错的地方

- `d_model` 不能被 `num_heads` 整除。
- 忘记给 K 转置最后两维。
- mask 形状不能广播到 `[B, H, T, S]`。
- transpose 后直接 view，忘记 `.contiguous()`。
- logits 和 labels 没有错开一位。
- loss 没有忽略 padding token。
- decoder 推理时没有只取最后一个位置。

## 一句话总结

Transformer 里的大多数模块都保持：

```text
[batch, seq_len, d_model] -> [batch, seq_len, d_model]
```

Attention 内部会短暂变成：

```text
[batch, heads, seq_len, head_dim]
```

最后输出到词表时才变成：

```text
[batch, seq_len, vocab_size]
```

只要这三种形状不乱，Transformer 代码就会清楚很多。
