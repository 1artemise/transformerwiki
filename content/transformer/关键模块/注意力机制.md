注意力机制是 Transformer 的核心。
如果只用一句话说，它做的事情是：**当模型理解某个词时，自动判断这句话里哪些词更重要，然后多看它们几眼。**
## 为什么需要注意力

在 Transformer 之前，处理序列常用 RNN、LSTM 这类模型。它们读句子的方式很像人从左到右读：

```text
我 -> 喜欢 -> 吃 -> 苹果
```

这样当然能读，但有两个问题：

1. 很难并行。必须读完前面的词，才能读后面的词。
2. 长距离依赖容易丢。句子很长时，前面的信息传到后面可能已经变弱了。

比如：

```text
这本我昨天在图书馆借到的、封面很旧但是内容很新的书，非常好看。
```

“好看”真正评价的是“书”，但中间隔了很多词。模型要理解这句话，就不能只看附近几个词，它得知道远处哪个词和当前词有关。

注意力机制就是为了解决这个问题：**让每个词都能直接看见整句话里的其他词。**

## 自注意力是什么

自注意力（Self-Attention）里的“自”，意思是：一句话内部的词彼此互相看。
比如句子：
```text
我 喜欢 吃 苹果
```
当模型处理“吃”时，它会问：
```text
我和吃有多相关？
喜欢和吃有多相关？
吃和吃有多相关？
苹果和吃有多相关？
```
如果模型发现“苹果”和“吃”最相关，那么理解“吃”时就会更多吸收“苹果”的信息。
所以自注意力不是固定规则，而是模型自己学出来的“该看谁”。
## Q、K、V 是什么

Attention Is All You Need 里最容易卡住的就是 Q、K、V。
先别急着背名字，我们用生活里的“查资料”来理解：

- Q（Query）：我现在想找什么？
- K（Key）：每个词能提供什么线索？
- V（Value）：每个词真正携带的信息内容。
比如当前词是“吃”，它的 Q 可能在问：
```text
谁是被吃的东西？
```
而“苹果”的 K 可能刚好像是在回答：
```text
我是一个食物。
```
于是“吃”和“苹果”的匹配分数就会很高。
最后模型不是直接拿 K，而是拿 V。因为 K 只是用来匹配的索引，V 才是实际要汇总的信息。

可以记成：

```text
Q 和 K 算相关性
softmax 把相关性变成权重
权重去加权 V
```

## Q、K、V 从哪里来

Q、K、V 不是原始输入里天然带的三个东西。

它们是同一个输入向量经过三个不同的线性层变出来的：

```text
Q = XW_Q
K = XW_K
V = XW_V
```

这里的 `W_Q`、`W_K`、`W_V` 都是可学习权重。
训练时，模型会通过梯度不断调整它们。

为什么要分成三套权重？

因为“用来提问的表示”“用来匹配的表示”“真正携带信息的表示”不一定应该一样。

比如同一个词“苹果”：

```text
作为 Q：它可能在问“谁在修饰我？”
作为 K：它可能提供“我是食物/名词/宾语”的线索
作为 V：它携带“苹果这个词的语义信息”
```

把三者拆开，模型就有更大的自由度。

## 矩阵维度怎么理解

假设：

```text
batch_size = 2
seq_len = 4
d_model = 8
```

输入 `X` 的形状是：

```text
X: [2, 4, 8]
```

意思是：

```text
2 个句子
每个句子 4 个 token
每个 token 用 8 维向量表示
```

经过线性层后：

```text
Q: [2, 4, 8]
K: [2, 4, 8]
V: [2, 4, 8]
```

然后做：

```text
QK^T
```

对每个 batch 来说，就是：

```text
[4, 8] @ [8, 4] = [4, 4]
```

这个 `[4, 4]` 就是注意力分数矩阵。

它表示：

```text
第1个 token 看第1/2/3/4个 token 的分数
第2个 token 看第1/2/3/4个 token 的分数
第3个 token 看第1/2/3/4个 token 的分数
第4个 token 看第1/2/3/4个 token 的分数
```

所以 attention 的核心不是只算一个分数，而是一次性算出“每个 token 看每个 token”的关系图。
## 注意力公式

论文里的缩放点积注意力公式是：
```text
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k))V
```

拆开看就不吓人：
### 1. QK^T
这一步是在算每个词和每个词之间的相关性。
如果两个向量方向接近，点积就大，说明它们更相关。
### 2. 除以 sqrt(d_k)
这是为了防止点积结果太大
如果分数太大，softmax 会变得特别极端，几乎只看一个词，训练会不稳定。
所以除以 `sqrt(d_k)` 相当于把分数压一压。

为什么维度越大点积越容易变大？

因为点积是很多维度相乘再相加：

```text
q · k = q1k1 + q2k2 + q3k3 + ...
```

维度越多，加起来的项越多，结果的方差通常越大。
softmax 遇到特别大的分数，会变得很尖锐：

```text
[20, 1, 0] -> [几乎 1, 几乎 0, 几乎 0]
```

这样梯度会变小，模型很早就死盯某个位置，不利于训练。
除以 `sqrt(d_k)` 是一个简单但有效的缩放。
### 3. softmax
把相关性分数变成概率，也就是注意力权重。
对应笔记：[softmax](../前置知识/softmax.md)

### 4. 乘以 V

最后用注意力权重去加权求和 Value。
比如：
```text
苹果权重 0.7
喜欢权重 0.2
我权重 0.1
```
那当前词的新表示里，“苹果”的信息就占得最多。

## Multi-Head Attention 是什么
多头注意力就是同时做多组注意力。
为什么要多组？
因为一句话里的关系不止一种。
还是这句：
```text
我 喜欢 吃 苹果
```
一个头可能关注“动词和宾语”：
```text
吃 -> 苹果
```
另一个头可能关注“谁在做动作”：
```text
喜欢 -> 我
```

再一个头可能关注词序或修饰关系。
如果只有一个注意力头，它只能把很多关系挤在一个空间里学；多头注意力相当于给模型多个视角，让它同时从不同角度理解句子。

流程大概是：
```text
输入
  ↓
切成多个头
  ↓
每个头各自做注意力
  ↓
拼接起来
  ↓
再过一个线性层
```

更具体一点，假设：

```text
d_model = 512
num_heads = 8
```

每个头通常处理：

```text
d_head = 512 / 8 = 64
```

也就是每个头不拿完整 512 维，而是拿一部分投影空间去算注意力。

每个头输出 `[seq_len, 64]`，8 个头拼起来又回到：

```text
[seq_len, 512]
```

最后再经过一个输出线性层 `W_O`，让不同头的信息重新混合。

所以多头不是简单复制 8 份同样的 attention，而是 8 组不同参数学 8 种关系。

## Self-Attention 和 Cross-Attention

注意力不只有一种。

### Self-Attention

Self-Attention 里 Q、K、V 都来自同一段序列。

```text
Q = 输入自己
K = 输入自己
V = 输入自己
```

含义是：一句话内部的 token 互相看。

编码器里的注意力就是 self-attention。
GPT 这类 decoder-only 模型里也是 masked self-attention。

### Cross-Attention

Cross-Attention 里 Q 来自解码器，K 和 V 来自编码器。

```text
Q = 解码器当前状态
K = 编码器输出
V = 编码器输出
```

含义是：解码器正在生成输出时，回头查输入句子里哪些信息重要。

比如翻译时要生成 `cats`，解码器会去编码器结果里重点看“猫”。

## Masked Attention 是什么

在解码器里，还有一个 Masked Multi-Head Attention。
它的作用是：**生成当前词时，不能偷看未来的词。**
比如训练翻译模型时，目标句子是：
```text
I love cats
```
当模型正在预测 `love` 的时候，它只能看到：
```text
I
```
不能提前看到：
```text
cats
```

否则训练时就像考试提前看答案，效果会虚高，真正生成时就崩了。
所以 Mask 会把未来位置挡住，让模型只能看当前位置和之前的位置。

Mask 通常不是把未来位置真的删掉，而是把未来位置的 attention score 设成一个极小的数：

```text
score = -inf
```

这样经过 softmax 后，这些位置的概率就会变成 0。

```text
softmax([2, 1, -inf]) = [0.73, 0.27, 0.00]
```

这就是“看不见未来”的实现方式。

## Attention 的代价

Self-Attention 很强，但也有明显代价。

如果序列长度是 `n`，注意力分数矩阵是：

```text
n × n
```

所以计算和显存大致会随序列长度平方增长。

```text
长度 1024 -> 注意力矩阵约 1024 × 1024
长度 4096 -> 注意力矩阵约 4096 × 4096
```

这就是为什么长上下文模型、FlashAttention、KV Cache、PagedAttention 这些技术很重要。
它们本质上都在处理 attention 带来的计算和显存压力。

## 一句话总结

注意力机制让 Transformer 不再按顺序慢慢传递信息，而是让每个词都能直接和其他词建立联系。
它的核心可以记成：

```text
用 Q 找 K
用 softmax 算权重
用权重汇总 V
多头就是多种理解角度
Mask 是为了不偷看未来
```

再补一句训练角度：

```text
W_Q、W_K、W_V、W_O 都是会被训练更新的权重
attention 权重不是人工写死的规则，而是模型通过数据学出来的
```
