# Transformer 常见卡点

这篇专门放一些学 Transformer 时容易想不透的问题。

很多时候你不是看不懂公式，而是中间少了一层解释。

## 1. 模型到底学到了什么

模型学到的不是一句自然语言规则，而是一堆权重。

比如：

```text
Embedding 矩阵里的权重
Attention 里的 W_Q、W_K、W_V、W_O
Feed Forward 里的线性层权重
LayerNorm 里的 gamma、beta
输出层映射到词表的权重
```

训练前，这些权重大多是随机初始化的。
训练后，它们被数据和 loss 一步步调整。

所以“模型学会了语法/语义”这句话，落到实现上就是：

```text
某些输入经过这些权重计算后，更容易得到正确输出
```

## 2. 什么是权重

权重可以理解成模型内部的旋钮。

输入进来以后，模型会用这些权重做大量矩阵乘法。
不同权重会决定：

- 哪些特征更重要。
- 哪些 token 更应该互相关注。
- 哪些隐藏维度应该被放大或压小。
- 最后哪个词的概率更高。

比如一个非常简化的模型：

```text
输出 = 输入 × 权重
```

如果权重大一点，输入对输出的影响就大一点。
如果权重小一点，输入对输出的影响就小一点。

真实 Transformer 复杂很多，但底层仍然是大量这样的加权计算。

## 3. 权重为什么会变化

因为训练时有这条链路：

```text
预测 -> loss -> 梯度 -> 优化器 -> 更新权重
```

只要梯度存在，学习率不为 0，参数被优化器管理，权重就会变化。

对应笔记：[[前置知识/梯度与反向传播|梯度与反向传播]]

## 4. 权重什么时候不再变化

常见情况有五种：

- 推理阶段：只生成结果，不反向传播，不更新权重。
- 梯度接近 0：更新量太小，权重几乎不动。
- 学习率接近 0：即使有梯度，步子也非常小。
- 参数被冻结：比如微调时只训练一小部分参数。
- 参数没有传给优化器：算了梯度也不会被 `optimizer.step()` 更新。

所以看到权重没变，要顺着检查：

```text
requires_grad 是不是 True？
loss.backward() 有没有执行？
参数有没有 grad？
optimizer 里有没有这个参数？
optimizer.step() 有没有执行？
学习率是不是太小？
```

## 5. loss 不降是不是模型没学

不一定。

loss 不降可能是：

- 模型真的没学到。
- 学习率不合适。
- 标签错了。
- mask 错了。
- 梯度断了。
- 数据太少或太乱。
- batch 太小，波动太大。
- 模型太小，表达能力不够。

判断时不要只看一个 batch。
更应该看一段时间的趋势：

```text
训练 loss
验证 loss
梯度范数
学习率曲线
生成样例
```

## 6. loss 越低一定越好吗

训练 loss 越低，不一定越好。

如果训练 loss 下降，验证 loss 也下降，通常是好事。
如果训练 loss 下降，验证 loss 上升，可能是过拟合。

这说明模型不是学到了通用规律，而是开始背训练集。

对应笔记：[[前置知识/正则化|正则化]]、[[前置知识/DropOut|DropOut]]

## 7. Attention 权重是人工设定的吗

不是。

我们人工设定的是计算形式：

```text
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k))V
```

但 Q、K、V 从哪里来？

```text
Q = XW_Q
K = XW_K
V = XW_V
```

这里的 `W_Q`、`W_K`、`W_V` 是训练出来的。

所以 attention 权重不是我们手写“吃应该看苹果”，而是模型在大量数据里学出：在某些上下文下，“吃”和“苹果”的匹配分数应该更高。

## 8. 为什么 attention 后还要 Feed Forward

Attention 负责 token 之间交换信息。

但交换完以后，每个位置还需要自己加工一下。

```text
Attention：横向交流
Feed Forward：纵向加工
```

如果只做 attention，模型只是把别人的信息混进来。
Feed Forward 给每个位置提供了更强的非线性变换能力。

对应笔记：[[前置知识/前馈神经网络|前馈神经网络]]

## 9. 为什么 Add 和 LayerNorm 总是一起出现

Add 负责保留原始信息，并让梯度有捷径。

LayerNorm 负责把数值分布拉稳定。

可以这样理解：

```text
Add：别把原来的东西弄丢
LayerNorm：别让数值变得太乱
```

Transformer 堆很多层后，如果没有这两个东西，训练会很不稳定。

对应笔记：[[前置知识/Add|Add]]、[[前置知识/LayerNorm|LayerNorm]]

## 10. 训练时模型能看答案吗

能，但有限制。

训练 decoder 时，模型会看到正确答案的前半段，用它来预测下一个 token。

比如目标是：

```text
I like cats
```

预测 `cats` 时，模型可以看到：

```text
I like
```

但不能看到：

```text
cats
```

所以要加 causal mask，防止偷看未来。

## 11. 推理时模型会自动学习吗

不会。

你问模型一个问题，它只是用固定权重算出回答。

推理时没有：

```text
loss.backward()
optimizer.step()
```

所以权重不会变。

如果希望模型真的学进新知识，需要训练、微调、LoRA、RAG 或修改外部知识库。

## 12. 为什么 Transformer 可以并行训练，却不能一次生成整句话

训练时，目标句子已经在数据里，所以可以用 mask 一次性计算每个位置的预测。

推理时，后面的 token 还不存在。

模型必须先生成第一个 token，再把它放回输入，继续生成第二个。

```text
训练：答案已知，可以并行算
推理：答案未知，必须一步步生成
```

这就是自回归生成。

## 13. 为什么大模型需要那么多数据

因为参数很多。

参数越多，模型能表达的模式越复杂，但也越容易乱学或背数据。

大量数据能让模型反复看到不同上下文里的语言规律，让权重逐渐形成比较稳定的统计模式。

这不是简单记忆一句话，而是在很多样本里调整同一套权重。

## 14. 学 Transformer 最应该抓住什么

先抓住这条主线：

```text
token -> embedding -> position -> attention -> add/norm -> feed forward -> logits -> loss -> gradient -> update
```

如果这条线是通的，后面的 GPT、BERT、ViT、FlashAttention、KV Cache 都是在这条线的某个位置做变化或优化。

## 15. 为什么我看懂公式，代码还是写不出来

大概率是维度没走顺。

Transformer 代码里的核心不是单个公式，而是张量在这些形状之间来回变：

```text
[B, S, D]
[B, H, S, Dh]
[B, H, S, S]
[B, S, Vocab]
```

只要不知道每一步形状，就会在 `transpose`、`view`、`mask`、`loss reshape` 上反复出错。

对应笔记：[[关键模块/张量维度流|张量维度流]]

## 16. 为什么推理优化经常讲 KV Cache

因为生成时模型是一个 token 一个 token 往外吐。

历史 token 的 K/V 已经算过，如果每一步都重算，会浪费大量计算。

KV Cache 的核心就是：

```text
旧 token 的 K/V 缓存起来
新 token 只算自己的 Q/K/V
```

它用显存换速度，是大模型推理的基础优化。

对应笔记：[[推理/KV Cache|KV Cache]]
